# Islami — Project Structure

Flutter app (Arabic / RTL) with Mushaf, Hadith, Sebha, Radio/Reciters, Downloads, and Prayer Times.
Flutter 3.35 · Dart 3.9 · state: `provider` (`ChangeNotifier`) · DI: `get_it` + `injectable`.

## Folder layout

```
lib/
├── main.dart                 # bootstrap, configureDependencies(), MaterialApp + named routes
├── di/
│   ├── injection.dart        # getIt + configureDependencies()
│   └── injection.config.dart # GENERATED by build_runner — never edit
├── domain/repositories/      # abstract repository contracts (XRepository)
├── data/<feature>/           # XRepositoryImpl, XLocalDataSource, XRemoteDataSource
├── models/                   # ALL models (one model per file, fromJson/toJson, copyWith)
├── services/                 # app-wide services (audio, downloads, alarms, notifications, location…)
├── providers/app_providers.dart  # app-wide MultiProvider
├── ui/
│   ├── widget/               # widgets shared across the whole app (FadeIn, PressableScale…)
│   ├── home/                 # home shell: bottom bar + tabs
│   │   ├── home_screen.dart
│   │   ├── view_model/
│   │   ├── widget/           # widgets shared by the home tabs (mini player, search bar…)
│   │   └── tabs/<tab>_screen/{<tab>_screen.dart, view_model/, widget/}
│   └── <name>_view/{<name>_view.dart, view_model/, widget/}   # pushed screens
└── utils/                    # app_colors, app_styles, app_assets, app_routes, app_themes,
                              # app_animations, shared_preferences, network_utils, calculators…
```

Nested screens live inside their parent screen folder (e.g. `moshaf_screen/moshaf_index_view/`,
`sebha_screen/azkar_view/`), each with its own `view_model/` and `widget/`.

## Layers & dependency direction

```
UI (View) ──> ViewModel ──> Repository (domain, abstract) <── RepositoryImpl (data) ──> DataSource
                  │                                                                        
                  └──> Service (services/)            models/ and utils/ are used by every layer
```

- `ui` → `domain`/`data`/`services`/`models`/`utils`. Nothing outside `ui` imports from `ui`.
- `data` implements `domain`. ViewModels depend on the **abstract** repository, never on `*Impl`.
- Simple read-only features without a repository use the data source directly from the ViewModel
  (e.g. `SermonsLocalDataSource`, `SharawyLocalDataSource`, `MoshafLocalDataSource`).
- Data sources do one job: read JSON assets (`rootBundle`), call HTTP (`package:http`), read/write
  SharedPreferences, or call a `MethodChannel`. They log with `log()` and `rethrow`.
- Repositories combine sources (cache-or-network, merging lists, offline fallback).

## Naming

| Thing | Convention | Example |
|---|---|---|
| Abstract repository | `XRepository` in `domain/repositories/x_repository.dart` | `TimeRepository` |
| Implementation | `XRepositoryImpl` in `data/<feature>/x_repository_impl.dart` | `TimeRepositoryImpl` |
| Data sources | `XLocalDataSource` / `XRemoteDataSource` | `RadioRemoteDataSource` |
| ViewModel | `XViewModel` in `view_model/x_view_model.dart` | `HadithViewModel` |
| Screens | tabs: `XScreen`; pushed screens: `XView` | `TimeScreen`, `QiblaView` |
| Files | `snake_case.dart`, one public class per file | |
| Colors | `AppColors.<colorName>` | `primaryColor`, `offWhite` |
| Text styles | `AppStyles.<color><Weight><size>` | `primaryBold24`, `whiteBold12` |
| Routes | `AppRoutes.<name>RouteName` | `qiblaRouteName` |
| Prefs keys | `SharedPreferencesKay.<name>` + top-level `getX`/`saveX` functions | `getAzanEnabled()` |

Legacy: the home tabs use `*_screen` folder/class names; screens added later use `*_view`.

## Dependency injection

- `configureDependencies()` runs first in `main()`, and also at the top of every background-isolate
  entry point (`adhanRefreshCallback`, `downloadForegroundStartCallback`) because each isolate has
  its own `GetIt`. It is idempotent.
- Regenerate after adding/changing an annotated class:
  `dart run build_runner build`

| Lifetime | Used for |
|---|---|
| `@lazySingleton` | stateless data sources, `@LazySingleton(as: XRepository)` impls, app-wide services (`AudioPlayerService`, `ConnectivityMonitor`, `QuranDownloadManager`, `AdhanAlarmScheduler`, notification services…) |
| `@injectable` (factory) | ViewModels with dependencies; services holding per-operation state (`QuranAudioDownloadService`) |
| `@factoryParam` | ViewModels that also need a screen argument (`getIt<ReciterDownloadViewModel>(param1: reciter)`) |
| no DI | ViewModels with no dependencies (`AzkarViewModel`, `RiyadChapterViewModel`, `SplashViewModel`…) and pure static helpers (`NetworkUtils`, `QiblaCalculator`, `NextPrayerCalculator`, `AppMessenger`) |

No eager `@singleton` is used, so registering in a background isolate creates nothing.
Constructor injection only (positional `this._dep`); `getIt<T>()` is called only at composition
points: `main.dart`, `AppProviders`, `ChangeNotifierProvider.create`, `initState` of screens that
own their ViewModel, and isolate entry points. Widgets read shared services through Provider
(`context.read<AudioPlayerService>()`).

## State management (provider)

- Screen ViewModel: `ChangeNotifierProvider(create: (_) => getIt<XViewModel>())` at the top of the
  screen; widgets use `Consumer<XViewModel>` / `Selector` (records for multi-value selects) /
  `context.read`.
- Screens needing lifecycle hooks create the ViewModel in `initState` and expose it with
  `ChangeNotifierProvider.value`, disposing it themselves (`MoshafScreen`, `MoshafHubView`).
- App-wide state (`AppProviders`): singletons via `ChangeNotifierProvider.value`; long-lived
  ViewModels (`RadioViewModel`, `DownloadsViewModel`) via `create` so Provider owns/disposes them.
- ViewModel state = public fields + `notifyListeners()`; loading/error as `isLoading` +
  `failureMsg`/`errorMessage` strings; user-facing failure text from
  `NetworkUtils.failureMessageFor(e)`.
- Navigation lives in ViewModel methods that take `BuildContext` (`openQibla(context)`), always via
  `Navigator.pushNamed(context, AppRoutes.x, arguments: …)`.
- Search fields use `onChanged` (no `TextEditingController`), and their text is persisted in
  SharedPreferences.

## Routing

`MaterialApp.routes` in `main.dart`; names in `AppRoutes`. Arguments are read with
`ModalRoute.of(context)!.settings.arguments as T` inside the route builder, and route-scoped
ViewModels are created there. Pickers return a value with `Navigator.pop(context, value)`.
`MaterialApp.builder` stacks a global `DownloadProgressBanner` over every route;
`AppMessenger.scaffoldMessengerKey` lets services show snackbars.

## UI / UX & animation conventions

Shared timings live in `utils/app_animations.dart`:

| Token | Value | Use |
|---|---|---|
| `AppAnimations.press` | 120 ms | tap-down feedback |
| `AppAnimations.fast` | 220 ms | tab/section/state switches, selected-state changes |
| `AppAnimations.listMove` | 300 ms | list item shrinking/growing (favorites) |
| `AppAnimations.curve` | `Curves.easeOutCubic` | default curve |
| `AppAnimations.pressedScale` | 0.97 | pressed card scale |

Other durations used: icon swap 200 ms; mini player in/out 350 ms (`easeOutCubic` in / `easeInCubic`
out); mini player title/controls 300 ms; overlay bars show/hide 250 ms `easeInOut`; programmatic
page jumps 300 ms `easeInOut`; scroll-to-item 600 ms approach + 400 ms reveal `easeInOut`;
playful feedback (counters, check marks, sebha rotation) 280–450 ms `easeOutBack`.

- **Page transitions:** set once in `AppTheme.pageTransitionsTheme`: Android
  `ZoomPageTransitionsBuilder(backgroundColor: AppColors.blackColor)` (no white flash on the dark
  UI), iOS `CupertinoPageTransitionsBuilder`. No per-route `PageRouteBuilder`.
- **Splash:** native splash is preserved, the Flutter `SplashView` precaches its images, removes the
  native splash, then plays one 2400 ms `AnimationController` with staggered `Interval`s
  (fade/slide/scale layers), holds 900 ms, then `pushReplacementNamed(home)`.
- **Tab navigation:** `HomeTabsView` = `IndexedStack` (keeps state), lazy-builds a tab on first visit,
  disables tickers/focus of hidden tabs (`TickerMode`, `ExcludeFocus`), and fades the new tab in
  (`fast`). Bottom-bar icons get an `AnimatedContainer` pill when selected.
- **Tap feedback:** wrap tappable cards in `PressableScale` (raw `Listener`, scales to 0.97 in
  120 ms, releases when the finger moves past `kTouchSlop`, never delays the tap).
- **Icon toggles:** `AnimatedIconSwitcher` (scale + fade, 200 ms); the child must have a changing
  `ValueKey` (e.g. `ValueKey(isPlaying)`). Play buttons swap to a small spinner while loading.
- **State switches (loading → error → content):** wrap each state in `FadeIn` with a distinct
  `ValueKey('loading' | 'failure' | 'content')` so it re-fades on change.
- **Loading:** centered `CircularProgressIndicator(color: AppColors.primaryColor)`.
- **Error:** `NoInternetRetryView(message, onRefresh)` (message + refresh `IconButton`) or a centered
  `AppStyles.primaryBold20/24` text; `OfflineRefreshHeader` shows a refresh icon only while offline.
- **Empty:** centered text (`'لا توجد نتائج'`) in `AppStyles.primaryBold20`.
- **Snackbars:** floating, `hideCurrentSnackBar()` before showing; helpers like
  `showNoInternetSnackBar` / `showPlaybackFailureSnackBar`.
- **Lists:** moving an item between lists animates with `FavoriteMoveTransition` (height + opacity,
  `listMove`); the ViewModel awaits `Future.delayed(AppAnimations.listMove)` before reordering.
  `ActiveAudioListView` smoothly scrolls to the playing item and back to top when search is tapped.
- **Micro-interactions:** `AnimatedContainer` for selected/active borders and glows,
  `AnimatedCounterText` (scale + fade per number), `TweenAnimationBuilder` for progress fills,
  `AnimatedScale(easeOutBack)` for completion badges, `AnimatedSlide` + `AnimatedOpacity` for
  overlay bars, `AnimatedSize` + `AnimatedSwitcher` when content changes size.
- **Perceived performance:** `precacheImage` for the next/previous page and splash layers;
  `compute()` for big JSON parsing; `Selector` to avoid per-second rebuilds.
- Full-screen background images go through `ScreenBackground` (sized from screen height so the
  mini player does not move them).

## Code style

- Simple, beginner-readable Dart; explicit types where helpful; `const` widgets.
- Every method has a one-line `///` comment saying what it does.
- Custom widgets in their own file in the nearest `widget/` folder — no functions that return
  widgets (non-widget builders such as `BottomNavigationBarItem` helpers are fine).
- Colors, styles, assets, routes, and prefs only through `utils/` (no hardcoded values).
- `package:islami/...` imports only (no relative imports).
- Errors: data sources `log()` + `rethrow`; ViewModels catch and set a user-facing message.
- Background isolates: top-level `@pragma('vm:entry-point')` functions; reload prefs with
  `reloadPreferences()` before reading.
